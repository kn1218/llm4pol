<objective>
Commit one instance of every schema the tracer uses and put each in the gate's schema inventory,
so that the four schemas are validated on every gate run and the instances cannot drift from the
record the code writes.

Purpose: CLAUDE.md - a payload with no schema has no guard - and the 03-01 precedent: a schema is
followed by its committed example in the inventory. The ledger instances are not illustrations:
they are lines of the tracer run under an injected identity, compared byte for byte by a test.

**Fourteen files, and why the plan is not split.** Eleven of them are generated JSON documents of
a few hundred bytes each, written by one script and guarded by one test file; the inventory step
loads one document per instance (F-57), so eight ledger lines are eight files. The remaining three
files are the inventory table and two test files. A split into "ledger examples" and "the other
three" would cut one commit pair in two and edit the same inventory table and the same count
assertion twice.

Inventory after this plan: 7 entries, 14 instances - 3 existing, 1 problem spec, 1 selection plan,
1 meta, 8 ledger. Plans 04-07 and 04-08 add `usage.json` and `run_summary.json` with their
schemas, to 9 entries and 16 instances.

Workstation rules as in 04-01: `git commit -F <file>`; `--max-count` with git; `PYTHONPATH=src`.
</objective>
