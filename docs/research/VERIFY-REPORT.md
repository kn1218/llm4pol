## Extra findings (README.md / CLAUDE.md / scaffold)

No statement in README.md or CLAUDE.md was found to be false. The following are pre-charter commitments or precision points the lead engineer should be aware of:

- **F1 (architecture commitment)** `env/pixi.toml` fixes a scientific stack before any charter: scikit-learn, pydantic, pyarrow, jsonschema, scipy alongside pandas/rdkit/openpyxl, Python 3.13 only, conda-forge only, platforms win-64 + linux-64 (comment: "Linux/dirac"). None of this is required by the current scaffold (only `llm4pol.__version__` and the manifest test). The lock file (212 KB) therefore already encodes these choices; the charter should confirm or prune them.
- **F2 (architecture commitment)** `.env.example` declares `LLM_PROVIDER=`, `OPENAI_API_KEY=`, `GEMINI_API_KEY=`, `CLAUDE_API_KEY=`. This presupposes a multi-provider LLM abstraction and a provider set that has not been decided (the LLM4MOF manuscript names gpt-5.2, gpt-5.4-nano, gpt-5.6-sol, claude-sonnet-5, claude-opus-5, claude-haiku-4.5 -- no Gemini). Also `CLAUDE_API_KEY` is not the Anthropic SDK's canonical variable (`ANTHROPIC_API_KEY`); harmless as a placeholder but easy to trip over later.
- **F3 (process commitment)** `CLAUDE.md` fixes the governance frame before a charter exists: the charter's filename (`docs/MASTER-PLAN.md`), a four-level precedence order including `.planning/REQUIREMENTS.md` (a GSD artifact), "This project uses the GSD workflow", conventional commits "scoped by GSD plan id", and `pixi` + `import-linter` as the gate. These mirror CALF20 conventions rather than an owner decision for LLM4POL. `README.md` line 43 also promises "there is no CI-only variant" -- true of `ci.yml` today, but CI has never executed (no commits, no remote), so the CI claims in README/report are untested.
- **F4 (precision)** `README.md` line 12 says "a 42,557-row copolymer CSV". The audit (`DATA-FOUNDATION-REPORT.md` section 1 row 36) reports 42,559 physical records of which pandas parses 42,557 because one corrupt record swallows neighbours. "42,557 parsed rows" is accurate; "42,557-row" understates the file by two records. Same figure appears in `data/README.md` and `docs/audit/README.md`.
- **F5 (no-modification scope)** Under `C:/Users/molsim/Dropbox/Work to do/LLM4POL` two tool-state directories exist that are not part of the user's data: `.omc/state/` (idle-notif-cooldown.json, hud-stdin-cache.json, agent-replay-a0b03baf-...jsonl, sessions/a0b03baf-...; mtimes 16:29:30-16:38:51 KST 2026-09-11) and `.ruff_cache/0.12.0` (15:11:26 KST). They were written by the orchestrating session's OMC hooks / anaconda ruff running with that folder as cwd, not by the bootstrap commands, and they sync into Dropbox. The three data files and the proposal are byte-identical and their mtimes are the July 2026 originals. The literal wording "nothing under ... was modified" should be read as "no user file was modified".
- **F6 (minor)** `README.md` line 22 lists `.planning/` in the layout although the directory does not exist ("none yet" is stated, so not false). C9's phrase ".planning/ tracked as in CALF20" only means no ignore rule excludes it.
